# C# skin runtime (Design PR #33, schema v2)

Hot-updatable note skins for Cytoid: the same `skin.json` the Design repo
compiles drives the Unity renderer. Implemented after the independent C#
architecture review (frontend compiler + flat evaluation graph + stateless VM,
reusing the proven `FlatGeom` tessellation and `FlatMeshBuilder` upload path).

## Layout (pure C# unless noted)

| File | Ports | Role |
|---|---|---|
| `SkinTiming.cs` | `tokens.ts`, `skin/slots.ts` | engine clock constants, slot registry, slotProgress |
| `SkinColorMath.cs` | `core/color.ts` | exact `mix` (OKLab, premultiplied alpha, 8-bit quantization), hex alpha |
| `SkinPalette.cs` | `palette.ts` | shade scales, neutral ring band, `ringTone`, `gradePalette` (400 verbatim) |
| `SkinInputs.cs` | `skin/inputs.ts`, `notes/types.ts` | `resolveInputs` / `resolveBodyInputs`, `SkinDrawContext` |
| `SkinDocument.cs` + `SkinJson.cs` | `skin/schema.ts` | strict parse (unknown keys rejected, zod-equivalent checks) |
| `SkinValidator.cs` | `skin/validate.ts` | whole-document validation, input availability, budgets |
| `SkinIr.cs` + `SkinCompiler.cs` | `skin/runtime.ts`, `skin/compile.ts` | folded expressions, tracks, gates, merged frames, slot/fallback assembly |
| `SkinPainter.cs` | interpreter draw path | stateless VM: envs, transform/opacity stacks, tessellation into `FlatMeshBuilder` |
| `FlatSkinRuntime.cs` | *(Unity boundary)* | registry, background compile, context adapter, dev toggle |

The pipeline runs off the main thread up to tessellation: parse → validate →
compile is pure C# (no UnityEngine), so skins can be compiled on a worker and
swapped atomically (`FlatSkinRuntime.TryLoad` compiles user skins against the
built-in as fallback; incomplete kinds and each `(kind, feedback mode)` group
inherit from it, exactly like `compileSkin(json, fallback)`).

## Verification

`dotnet run --project Tools/SkinProbe` replays the golden corpus generated by
`Tools/SkinProbe/golden-skin.ts` (run from the cytoid-design checkout — see its
header) through the C# port:

```
scenes replayed: 6128
value comparisons passed: 470466, failed: 0
draw pass: 7814766 vertices, steady-state allocation 0.0 B/scene
```

Scene-level parity covers every slot × driver grid × context (approach 0.5/1.2/3,
both directions, all grades, custom seed/ring variants, body options): node
structure, transforms, opacities, gates, windows, track sampling, easings,
colors as exact strings. The draw pass additionally exercises the tessellation
path (no exceptions, no NaN) and proves **zero steady-state GC allocation** in
the pure painter.

### Editor tests + performance harness

```
Unity -batchmode -nographics -projectPath . -runTests -testPlatform EditMode \
       -testFilter "SkinRuntime" -testResults skin-results.xml -logFile skin-tests.log
```

`SkinRuntimeSeamTests` covers the production seam (context fill + paint + fused
upload with a real `FlatNoteMesh`): **0 B/frame after warm-up**, deterministic
retry on poisoned slots (the renderer's once-only fallback gate), image-skin
rejection leaving the registry untouched, context reuse without stale state,
and painter survival across hot skin swaps.

`SkinRuntimePerfTests` A/B/C-measures 60 concurrent click heads (⅓ entering,
⅓ steady-held, ⅓ exiting; 150 warm-up + 300 measured frames) and writes
`skin-perf-report.json` (SKIN_PERF_JSON overrides). All three phases run the
**same paint workload and steady-skip contract** (40.1 notes processed/frame;
`processed` vs `uploads` are reported separately — skin-eval uploads by

design nothing):

| phase | ms/frame (editor, mono JIT, -nographics) | processed/frame | uploads/frame | seam GC |
|---|---|---|---|---|
| imperative (`FlatClickNoteRenderer.DrawEnter` + upload) | ≈ 5.0 | 40.1 | 40.1 | 0 B/frame |
| skin-full (`FillHeadContext` + `SkinPainter` + fused upload) | ≈ 7.7 | 40.1 | 40.1 | 0 B/frame |
| skin-eval (painter only, no upload) | ≈ 6.1 | 40.1 | 0 | 0 B/frame |

These are **smoke/relative numbers only** — editor-loop mono JIT is not device
data. What they attribute: the paint itself costs ≈ 1.2× the imperative draw
(6.1 vs 5.0 ms/frame at equal workload); the fused upload adds ≈ 1.6 ms/frame
(≈ 0.04 ms per upload). Inside the paint, tessellation ≈ 1.80 s vs ≈ 0.02 s
track/expression evaluation over the window (SkinPaintStats) — the
interpreter is not the cost, `FlatGeom` tessellation + upload is (as predicted
by the architecture review). Steady-held heads skip both paint and upload
entirely (driver-keyed rebuild + opacity-keyed upload), matching the
imperative renderer's caching. With `-nographics` the render pass is skipped
(draw/SetPass read 0); run without `-nographics` for draw-call comparison.
Draw calls stay 1 per note mesh in both paths.

**Device gates still pending** (must be measured on low-end Android/iOS
builds with IL2CPP before enabling SkinMode): p95 main-thread ms, GC alloc
per frame via ProfilerRecorder on-device, draw-call parity, thermal behavior.

### Profiler markers

Static `ProfilerMarker`s (zero overhead when not profiling) split the seam:
`Skin.Binding` (context/palette lookup), `Skin.Paint` (painter total),
`Skin.UploadCopy` (geometry transfer + opacity), `FlatNoteMesh.Upload`
(mesh upload). `SkinPaintStats` mirrors the evaluate/tessellate split as pure
C# counters for the harness.

## Engine / skin responsibility contract (skin mode)

- **skin owns**: enter size curve (`transform.scale` tracks), enter fade-in,
  head exit fade + rewind playback (the exit slot's `fade` track and
  `exitRewindEnd` input).
- **engine keeps**: position/rotation, storyboard `SizeMultiplier` and opacity,
  chart/model opacity, global opacity multipliers, `HideNotes`, visibility
  windows, pooling, colliders.
- **disabled in skin mode** (`FlatNoteRendererBase`): `ScaleAt`/`EnterScale`
  curve blending, the 2× intro opacity ramp, head `ExitAlpha`/`ExitRewind`
  (the detached `FlatNoteExitVisual` keeps only its timing cutoff).
- `initial_scale` interaction is unresolved until the contract is signed off
  with Design (Phase 0 item); skin mode currently ignores it.

## Current status & documented deviations

The runtime is behind `FlatSkinRuntime.SkinMode` (**off by default**; for dev
A/B testing it currently rides the *experimental note design* player setting,
see `GameConfig.OnGameLoaded`):

- Head visuals (enter / exit / miss-riding-exit) draw from skin slots for
capability-clean kinds; the per-frame hot path is allocation-free
(`readonly struct SkinSinks` on the stack, per-renderer reused
`SkinDrawContext` filled in place; detached exits capture an independent
  context snapshot at capture time).
- Rebuilds are driver-keyed (enter progress / exit time / palette / external
  invalidation): steady-held heads paint once and only re-upload on opacity
  changes. Upload is fused — design→world conversion applies per-part opacity
  in the same pass, with no intermediate builder copy (both paths).
- Hold bodies (clip) and the scanner triangle stay
  imperative until their phases land; drag connections moved to the required
  `chainLink` slot (6559409) with the engine owning the lead/trail window and
  the source head's approach fade; `loopUnder` draws under the press head
  on the head mesh rather than under the body (sorting-layer constraint,
  documented in FlatHoldNoteRenderer); feedback labels are screen-locked:
  the feedback slot's vertex range is counter-rotated against the FX's full
  world rotation (note heading + storyboard) every frame — the same
  KeepTextUpright contract as the imperative label — while the burst
  graphics keep riding the note's rotation (product spec).
- **isolate** groups are approximated by folding opacity into the subtree (the
  current Unity exit-fade behaviour); no offscreen compositing yet.
- **clip** (rect/circle) frames are CPU-clipped at emission. **image** frames
  paint only through the dedicated image sink (clear/feedback FX); every other
  draw path (heads, bodies, progress, drag actives) gates slots on `UsesImages`
  at draw time — heads fall back to classic rendering, bodies to the imperative
  fallback (`hold:body` today) — instead of dropping quads silently.
- **blend: add** routes to a second `FlatMeshBuilder` (as `FlatClearFx` does);
  note heads currently have no additive sink.
- Square caps on arcs render as butt; dashes on arcs/polys are capability flags.

## Rollout (remaining phases)

1. Hold/long-hold bodies: clip support (SDF shader or CPU scissor), body slots
   on `BodyMesh`, style-2 shortening.
2. Images + sequences: PNG decode → `Texture2DArray`, premultiplied uber
   shader, isolate RT atlas pass.
4. Player skin loading (zip/folder), palette priority (storyboard > player >
   defaults), binary cache keyed by JSON hash. (The skin meta palette section
   is parsed tolerantly but never consumed — game-config colours own the look.)
5. Built-in flat driven by the runtime as default; imperative path retired
   one release later.
